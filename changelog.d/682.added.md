Certify Microcosm builds published side by side in their own release folders (`releases/<release>/<build>/`, with no Hugging Face tag): a release manifest that names its `release` and `build` as strings is certified from that folder, its own files are pinned inside it at the certified revision, and its `build` names the certificate, so two builds of one release never match. Certification refuses such a build unless the repository's `releases.json` at `main` lists it and has not withdrawn it, and refuses any of its own files that is not a bare file name directly inside its folder. At import, a remote manifest that names another release or build than the bundle's pinned folder is refused. Manifests published before this layout are read as before.
