A US `Simulation.run()` stamps its output with the register of renamed stored inputs it was calculated under, an output format revision, and the stamp of the year file its input data was cut into, if any. `Simulation.load()` refuses a saved US output, and `Simulation.ensure()` runs it again, unless that stamp matches this release exactly. An output calculated before a rename was registered, or from a year file carrying an out-of-date stamp, is therefore not reused. The error says why, naming the renames the output may lack. Outputs saved before the stamp existed are calculated again once. A stamp or renames record behind a soft link that leads back to itself now counts as unreadable, for year files too, rather than raising.
