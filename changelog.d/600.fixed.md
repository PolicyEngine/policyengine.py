UK year files now record the source dataset they were cut from and the policyengine-core and policyengine-uk versions that cut them, as US year files do. `ensure_datasets` creates a UK year file again, and `load_datasets` refuses it, when the requested dataset now resolves to another source or another version is installed, so re-pinning a dataset such as `enhanced_frs_2024_25` or `populace_uk_2023` under the same name, editing a local source, or upgrading either package no longer reuses year files cut before. Deciding reads only each year file's stamp and whether it records its data year, and never downloads or reads the source. `create_datasets` stamps the year files only if the source file is still the one it materialized, and otherwise leaves them unstamped and raises `DatasetMaterializationError`. Requesting two different sources that share a name (and so would share year files) now raises `ValueError`. Year files written before this release are created again once. The stamp code the US and UK share now lives in `policyengine.provenance.year_file_stamp`.
